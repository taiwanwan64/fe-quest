実ブラウザ試験
- Chromium 144 を headless + DevTools Protocol で実際に起動。
- localhost (http://127.0.0.1:8765/) への遷移を試行。
- file:///mnt/data/.../index.html への遷移も試行。
- どちらも実行環境の管理ポリシーにより net::ERR_BLOCKED_BY_ADMINISTRATOR。
- chrome-error://chromewebdata/ へ遷移することを確認。
- よって「実ブラウザE2E PASS」とは記録しない。

v66で実装した耐久対策

1. ブラウザ戻る
- showScreen() と History API を連携。
- アプリ内戻るボタンは、履歴がある場合は前画面へ戻る。
- 直接起動など履歴がない場合だけ data-screen の既定画面へ戻る。
- popstate でも画面状態を同期。

2. 再読み込み復帰
- ホーム / 学習 / 苦手 / 問題 / 計画 / 範囲 / 模試 / 学習分析を安全復帰対象に設定。
- 最後にいた安全画面を localStorage に保存。
- レッスンは lessonId とページ番号を保存し、再読み込み後に同じページへ復帰。
- インタラクティブ操作の途中状態そのものは復元せず、そのページを安全に再表示。

3. 科目B総合実戦
- 20問の問題セット、回答、後で見るフラグ、現在問題、残り時間を保存。
- 15秒ごと＋回答/移動時に保存。
- 再読み込み後は同じ20問・同じ回答・残り時間から再開。
- 閉じていた時間も試験時間として経過させる。
- 時間切れなら古い再開データは破棄。
- 正式提出・ユーザーが明示的に終了した場合も再開データを削除。

4. PWA更新
- Service Workerの更新切替直前に現在位置と総合実戦を保存。
- controllerchangeによる再読み込み前にも保存。
- 更新後は復元エンジンが現在位置を再構築。

5. スマホ
- viewport-fit=cover / safe-area は既存仕様を維持。
- 重要操作のタッチ領域を44px以上へ。
- input/select/textarea は16px以上としてiOS入力時の自動ズームを抑制。
- コード系表示へ横スクロール保護。
- screen配下のmin-width:0、img/svg max-width:100%で横溢れを抑制。
- 390px以下でも科目カード、問題ナビが潰れにくい補正を追加。

検証
- JavaScript / Service Worker 構文確認
- Node VM DOM回帰
- localStorage UI復帰
- lesson page復帰
- B final回答/残り時間復帰
- safe-screen restore
- History API fallback
- 14px文字下限
- 参考資料名のUI漏出なし

実機で最終確認したい項目
- iPhone Safari / ホーム画面PWAでの戻る・再読み込み
- 科目B総合実戦を5問回答→再読み込み→回答保持
- Service Worker更新通知→更新→同じレッスンへ復帰
- 390px前後の縦画面で全主要画面の横スクロール有無
