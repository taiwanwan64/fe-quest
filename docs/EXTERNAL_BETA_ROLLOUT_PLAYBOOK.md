# FE QUEST — Small External Beta Rollout Playbook

Status: **READY AFTER PHYSICAL-DEVICE GO**  
Target cohort: **10〜30人**  
Production baseline: **v345 / profile schema v5**

## 1. この文書の役割

`docs/BETA_MEASUREMENT_PLAN_v346.md` で決めた「少人数・手動確認・自動トラッキングなし」という方針を、実際に招待するときの運用手順に落とす。

この文書は外部βを自動で開始する許可ではない。招待先、開始日、人数は人が決める。`docs/PHYSICAL_DEVICE_BETA_GATE.md` が PASS になるまでは招待しない。

## 2. 開始前チェック

すべて満たしてから最初の招待を送る。

- [ ] 物理デバイスβゲートが PASS
- [ ] production が `https://taiwanwan64.github.io/fe-quest/` の v345
- [ ] `privacy.html` が現行productionと一致
- [ ] `.github/ISSUE_TEMPLATE/beta-feedback.md` が利用可能
- [ ] クラウド同期は任意・local-firstのまま
- [ ] 既知のデータ消失 / 保存不能 / 起動不能 blocker がない
- [ ] β管理記録では氏名・メールアドレス等の不要な個人情報を記録しない運用を決めた

## 3. 招待の進め方

最終的な初期コホートは10〜30人とする。

運用上は、一度に全員へ広げるより、最初の数人の初回利用を確認して重大blockerがないことを見てから残りへ広げる方が安全。ただしこれは製品仕様ではなく、招待事故を小さくするための運用推奨である。

各テスターは公開リポジトリ上では実名で管理せず、必要なら `B01`, `B02` のような内部用コードだけを使う。実際の連絡先とコードの対応表が必要な場合は、公開GitHubリポジトリには置かない。

## 4. 招待文テンプレート

必要に応じて口調だけ調整し、内容は大きく変えない。

> 基本情報技術者試験の学習アプリ「FE QUEST」を作っていて、少人数のβテストに協力してくださる方を募集しています。  
> FE QUESTは、受験予定日や学習状況から「今日やること」を自動で組み、科目A・復習・科目B・模試までつなげる学習アプリです。  
> まだβ版なので、不具合や分かりにくい部分が残っている可能性があります。合格を保証するサービスではありません。  
> ログインは必須ではなく、基本の学習データは端末内に保存できます。クラウド同期は任意です。  
> 使ってみて「次に何を勉強するか考える負担が減ったか」「迷った画面があったか」を短く教えていただけると助かります。

本番URLとprivacyページは招待時に明示する。URLを短縮サービスへ勝手に置き換えない。

## 5. 初回利用後に聞くこと

長いアンケートにしない。中心価値を先に確認する。

1. 「今日の学習」から実際に学習を始められましたか？  
   **はい / いいえ**
2. 次に何を勉強するかを自分で考える負担は減りましたか？  
   **はい / どちらともいえない / いいえ**
3. 初回設定で迷ったところはありましたか？
4. 途中で「次に何を押せばいいか分からない」と感じた画面はありましたか？
5. データが消えた、保存されない、起動できないなどの問題はありましたか？

自由記述は短くてよい。「詳しい感想を書いてください」と負担をかけすぎない。

## 6. D1 / D3 / D7 / D30 の確認

`docs/BETA_MEASUREMENT_PLAN_v346.md` と同じ定義を使う。

各時点で、FE QUESTを使ったかだけをまず **はい / いいえ / 未確認** で記録する。アプリから学習履歴を自動送信して判定しない。

### D1

- 利用: はい / いいえ / 未確認
- 今日の学習から開始できたか
- 初回の大きな迷い / blockerがあったか

### D3

- 利用: はい / いいえ / 未確認
- 「何をやるか考えなくてよい」価値を感じているか
- 復習 / 科目B / 継続導線で迷いがあるか

### D7

- 利用: はい / いいえ / 未確認
- 継続した理由 / 止まった理由
- 学習レポート / 試験までのペース表示が理解できるか
- 改善すると戻ってきそうな摩擦があるか

### D30

- 利用: はい / いいえ / 未確認
- 習慣として残ったか
- 中心価値が持続したか
- 今後も使いたい理由 / 使わない理由

D30まで待たないと直せないという意味ではない。データ消失や起動不能など重大な問題はその時点で止めて修正する。

## 7. フィードバック経路

技術的な不具合を公開GitHub Issueへ投稿できるテスターには、`βフィードバック / 不具合報告` テンプレートを使ってもらう。

GitHubアカウントを持たないなど公開Issueが負担になる人には、運営者が選んだ既存の連絡手段で短いフィードバックを受け、必要なら個人を特定しない形に要約してIssue化する。βのためだけに新しい第三者トラッキング / フォームSDKをアプリへ追加しない。

公開Issueへ次を貼らせない。

- メールアドレス
- Magic Link
- 認証トークン / session情報
- JSONエクスポート全文
- localStorage / IndexedDB全量
- 再現に不要な個人情報

## 8. 不具合の優先度

### P0 — 即時停止候補

- 学習データの消失 / 意図しない上書き
- 起動不能が複数環境で再現
- 保存不能 / 復旧不能
- 認証情報や学習データの意図しない公開

→ 新規招待を止め、原因確認を優先する。

### P1 — 学習開始・継続blocker

- 初回設定を完了できない
- 今日の計画を作れない / 開始できない
- 主要ナビゲーションから先へ進めない
- 科目Bや模試など主要経路が実質利用不能

→ 原則として次の招待波を止め、修正を優先する。

### P2 — 価値を弱める摩擦

- 次に何をすべきか分かりにくい
- 表示の意味を誤解しやすい
- 復習 / 学習レポート / ペース表示の理解が難しい
- モバイルで操作しづらいが回避は可能

→ βを継続しながら頻度と影響を見て小さく修正する。

### P3 — 軽微

- 文言の細かな違和感
- 軽微な余白 / 見た目
- 学習を妨げない改善案

→ まとめて優先順位を付ける。

## 9. βを一時停止する条件

次のいずれかが見つかったら、人数を増やす前に止める。

- P0が1件でも合理的に再現する
- P1が複数人の初回利用を妨げる
- 保存 / 復旧 / クラウド競合でデータ安全性に疑義が出る
- privacyの説明と実際の挙動が一致しない
- 同じ重大摩擦が短期間に繰り返し報告される

単発の軽微なUI要望だけでβ全体を止める必要はない。

## 10. 何をまだ決めないか

10〜30人の初期βで十分な実測がない段階では、次を既定路線にしない。

- Premium / Paywallの実装
- 第三者行動分析SDKの導入
- 大規模広告出稿
- 大人数への一斉公開
- 学習ロジックの全面作り直し

まず確認するのは、**「今日やることを自分で考えずに済む」ことが実際の継続価値になるか**である。

## 11. β終了時の整理

最初のコホートについて、少なくとも次をまとめる。

- 招待数
- D1 / D3 / D7 / D30 の はい / いいえ / 未確認
- 今日の学習から開始できた人数
- 中心価値への はい / どちらともいえない / いいえ
- P0 / P1 / P2 / P3 の件数と代表例
- 最も多かった「止まる理由」
- 最も評価された価値

個別の学習正誤履歴を集めて集計するのではなく、必要最小限のβ管理記録と明示的な回答を使う。

次の学習者向けリリースは、この整理を見てから決める。
