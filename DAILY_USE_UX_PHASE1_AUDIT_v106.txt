FE QUEST PWA v106
Daily-use UX audit - Phase 1: Home / first action / visual priority

Goal
- Begin the full-screen daily-use audit requested for FE QUEST.
- Prioritize three questions: "What should I do now?", "Can I start quickly?", and "Is secondary information getting in the way?"

Changes
1. One-tap daily resume
- Added a single primary button directly under today's progress.
- If no task has been completed: "今日の学習を始める →".
- If some tasks are completed: "続きから再開 →".
- The button launches the first unfinished task from the existing daily-plan snapshot, so it does not create a second scheduling path.
- When all tasks are complete, it becomes disabled and displays "今日の学習は完了しました ✓".

2. Reduced home-screen competition
- "今日の復習候補" is now a collapsed secondary section labelled "復習候補を見る".
- Review candidates remain accessible, but no longer compete visually with the main daily plan on every app launch.

3. Removed nonfunctional header information
- Removed the static "LV.12" chip.
- XP and streak remain because they are live learning-continuity indicators; a fixed level number that did not reflect actual progress was unnecessary visual noise.

4. Removed misleading fixed-duration wording
- Home intro no longer says "60分の学習メニュー" because the user's configured study time and tapering phase can change the actual duration.
- It now explains the actual behavior: the app builds today's work from review schedule, weak areas, and progress.

5. Mobile behavior
- The new resume button is full-width and thumb-friendly.
- The collapsed review area becomes a normal single-column list on mobile rather than a horizontal card strip.
- This supports the prior no-horizontal-scroll direction.

Preserved behavior
- Daily-plan generation logic unchanged.
- Tapering / exam-day logic unchanged.
- Completion routing unchanged.
- Profile Schema v5 unchanged.
- Data protection / recovery behavior unchanged.
- Subject A question banks unchanged.
- Subject B algorithm / compound / security content unchanged.

Next UX audit stages
- Global navigation and screen naming: reduce overlapping destinations and make the difference between 学習 / 問題 / 苦手 / 計画 / 範囲 / 模試 immediately understandable.
- Course / lesson entry: reduce taps from learning list to the next useful learning action.
- Problem/review flow: remove duplicated explanations/actions and ensure one obvious primary next action.
- Subject B: simplify mode switching and reduce menu density.
- Results / planning / analytics: separate "act now" information from "inspect details" information.
