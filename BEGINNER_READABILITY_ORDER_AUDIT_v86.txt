FE QUEST v86 — 初学者向け理解順序・文章品質監査

目的
v85で130テーマの説明内容を厚くしたため、
v86では「情報量は十分でも、初学者が上から自然に理解できるか」を監査した。
特に、説明順序、重複する定型文、長文、略語の初出を対象とした。

参考資料との対応
- 科目Aは参考教科書の第1章〜第21章の体系を維持。
- 科目Bは参考教科書第22章のアルゴリズム/プログラミング・情報セキュリティという二本柱を維持。
- 問題集の公開問題・科目A/B各4セットの模擬問題は実戦水準を確認する材料として扱う。
- 市販教材の本文・問題本文は転載しない。

1. Core Aの説明順序を変更
v85:
まずここから
→ 用語
→ 解説
→ 比較
→ 重要
→ 計算・手順
→ 仕組み
→ 問題文の手掛かり
→ 注意

v86:
まずここから
→ 用語
→ 解説
→ 仕組み
→ 比較・計算/手順
→ 重要
→ 問題文の手掛かり
→ 注意

理由:
初学者は「何か」「どう動くか」を理解した後で、
比較・公式・要点整理へ進んだ方が理解しやすい。
「重要」を先に暗記させるのではなく、意味を理解してから要点をまとめる。

2. 31テーマの定型的な重複文を削除
v85の一部deep解説に、
「試験では〜という関係まで説明できるように整理する」
という同型の追記が残っていた。

問題:
- 直前の説明を言い換えているだけのケースが多い。
- テーマ固有の知識を増やさない。
- ユーザーが以前指摘した「どのレッスンにも出る学習方法・定型文」と同じ問題。

v86:
31テーマからこの定型追記を完全削除。
GENERIC_DEEP_FILLER = 0。

3. v85の「説明深度」QA自体も修正
v85の coreTopicExplanationVolume() は、
実際に画面へ表示している「解説」の中心段落 e.deep を計算対象へ入れていなかった。

v86:
- e.deep をQA指標へ追加。
- 画面に実際に表示する説明全体を評価。
- 新しい基準を540以上に設定。

現在:
- 130テーマ: すべて基準クリア
- 最小: 551
- 中央値: 640.0
- 540未満: 0テーマ

この数値は教材の良し悪しを文字数だけで決めるものではなく、
極端な説明不足を検出する下限QAとして使用する。

4. 長すぎる文を分割
全Core A本文を文単位で監査。

監査対象:
- まずここから
- lead
- deep解説
- 補足解説
- 重要
- 計算/手順
- 仕組み
- 問題文の手掛かり
- 注意

v86では最長文を80文字以下にするQAを追加。
実測最大: 79文字。

特に分割した例:
- OSの定義
- OSSの定義
- LAN/WAN
- SQL
- As-Is→To-Beの業務例
- MTBF/MTTRから稼働率を導く説明

長い一文へ複数概念を詰め込まず、
「定義 → 次の意味」の単位で文を分けた。
