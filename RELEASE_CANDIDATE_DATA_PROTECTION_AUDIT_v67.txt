FE QUEST v67 — リリース候補 データ保護・互換性監査

1. Profile schema v2
- profileSchemaVersion を導入。
- XP / streak / 8分野スキルを型・範囲チェック。
- lessonProgress / bProgress / securityBProgress を0〜100へ正規化。
- 履歴配列・統計オブジェクトが壊れた型なら安全な空値へ戻す。
- 既存 STORAGE_KEY=fequest_profile_v4 は維持し、v47〜v66系の現在データをそのまま移行。

2. 旧ストレージ移行
- 現行キーがない場合、fequest_profile_v3 / v2 / v1 を順番に探索。
- 読める旧データがあればschema v2へ正規化して現行キーへ移行。
- 元の旧キーは削除しない。

3. 自動保護スナップショット
- 通常saveProfile()と日次計画のsilent saveの両方でlast-goodを更新。
- 現在データJSONが破損した場合、まず破損rawを退避。
- last-goodが正常なら自動復旧して学習を継続。
- last-goodも利用不能な場合のみDEFAULT_PROFILEで起動。

4. バックアップ v2
- fequest-backup-v2
- appVersion / profileSchemaVersion / exportedAt / profile / checksum を保存。
- checksumはstable JSON + FNV-1a 32bit。暗号学的署名ではなく、ファイル破損・意図しない変更の検出用。
- JSON内のキー順が変わっても同じ内容なら同じchecksum。

5. インポート互換性
- v2: checksumを必須検証。
- v1: 従来バックアップを受入れ、schema v2へ移行。
- raw profile形式: 最低限の学習データとして妥当なら移行。
- 現アプリより新しいschemaのバックアップは拒否。
- 5MBを超える異常なファイルは拒否。
- 読込前に作成元版・日時・XP・学習完了数を表示。

6. 読込ミスからの巻き戻し
- バックアップ読込直前の現在データをPRE_IMPORTへ1回退避。
- 「直前の読込前データへ戻す」をアプリ・データ画面に表示。
- 巻き戻し後は退避を削除して二重復元を防止。

7. transient state
- バックアップ読込/巻き戻し時は、旧プロフィールに紐づく科目B総合実戦resumeとUI復帰位置をクリア。
- 新しいプロフィールと古い途中状態が混ざらない。

8. UI
- アプリ・データに「データ形式 v2」「自動保護 有効」を表示。
- 書き出しファイルが整合性チェック付きであることを明記。

検証予定/実施
- JavaScript / Service Worker構文
- v66相当データ → v67 migration
- 欠損フィールドを含む旧profile → 安全補完
- 破損current + 正常last-good → 自動復旧
- backup v2 export/decode roundtrip
- checksum改ざん検出
- backup v1 import migration
- pre-import rollback
- 既存学習進捗/XP/設定の保持
- built-in self check
