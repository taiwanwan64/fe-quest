FE QUEST v89 — 科目A 710問 選択肢・問題文品質監査

目的
v88で21章の章末12問を全テーマ横断型へ再設計した。
v89では問題の構成ではなく、710問そのものの「選択肢品質」と「問題文の反復」を監査した。

主な監査観点
1. 知識がなくても、明らかに別分野の選択肢を消すだけで正解できないか
2. 正解だけ問題文と同じ語を不自然に繰り返していないか
3. 同じ問題文テンプレートが大量に連続していないか
4. 正解だけ長い、または選択肢集合が重複していないか
5. 既存の正解・解説意味契約を壊していないか

1. 50問の基礎知識問題を「同分野の近い誤答」へ再設計
Core Aの各テーマにある knowledge 問題を横断確認したところ、
特に後半章で以下のような弱い誤答が残っていた。

例（旧）
「利用者問い合わせの単一窓口は？」
サービスデスク / CPU / DBMS / CA

これはサービスマネジメントを知らなくても、
CPU・DBMSを消すだけでかなり絞れてしまう。

v89
サービスデスク / インシデント管理 / 問題管理 / 変更管理

同じサービスマネジメント領域から選ばせるように変更。

別例（旧）
「顧客課題を総合的に解決する提供形態は？」
ソリューションビジネス / 単体テスト / DNS / ハッシュ

v89
ソリューションビジネス / 製品単体販売 / SIサービス / アウトソーシング

別例（旧）
「Webアプリへの攻撃対策に特化した装置/機能は？」

v89
FW / WAF / IDS / IPS

対象:
50問

各問題で

- 正解テキスト契約は維持

を付与。

2. 管理・ストラテジ後半での露骨な別分野誤答

残る0問はCh20内の

技術分野の無関係な選択肢ではない。

3. 既存問題6問を個別に高リスク改稿
自動的な同分野置換だけでは不十分な既存問題を個別改稿。

対象:
computer-15, sec-12, sec-20, mgmt-18, strat-18, strat-19

内容:
- sec-12: SQLインジェクション
  HTML文字サイズ / DBポート変更などを廃止。
  XSS対策、CSRF対策、パスワード保存対策と比較して
  「プレースホルダ付きパラメータ化クエリ」を判断させる。

- strat-19: CRM
  IP暗号化 / CPU高速化などを廃止。
  SCM / ERP / SFAの目的と比較する。

- strat-18: バリューチェーン
  データベース設計など別分野の選択肢を廃止。
  主活動と支援活動を混ぜた組合せから判断させる。

- sec-20: パッチ管理
  正規化 / デフラグなどを廃止。
  脆弱性診断 / 変更管理 / 構成管理との違いを判断させる。

- mgmt-18: インシデント管理
  財務管理などを廃止。
  変更管理 / 構成管理 / 問題管理と比較する。

- computer-15: 割込み
  暗号化などを廃止。
  ポーリング / DMA / スプーリングとの違いを判断させる。

4. 問題文テンプレート260問を分散
v88ではLinked問題に、
「『X』の説明・利用例として、最も適切なものはどれか。」
「『X』に関する説明として、最も適切なものはどれか。」
という大きな定型群が残っていた。

タイトル部分をXへ正規化して数えた場合:
v88 最大同一テンプレート: 88問
v88 20問以上使われるテンプレート: 4種類

v89:
- application / discrimination
- same-topic comparison
を別々の自然な複数テンプレートへ分散。

結果:
v89 最大同一テンプレート: 15問
v89 20問以上使われるテンプレート: 0種類
v89 stemAudit='v89-varied': 260問

問題内容や正解は変えず、
「毎回同じ生成文を読んでいる」感を減らした。

補足
文字列一致による「問題文と正解の語の重なり」検出は補助指標として利用した。
例えば
- OSI参照モデルの層名
- 集合計算の要素
- 配列トレースの数値
- クリティカルパスの遅延日数
では、問題構造上の正当な重なりも検出される。
そのため語の重なりだけを理由に機械的な改稿は行わず、
選択肢の同分野性・解答に必要な知識の有無を優先して判断した。

今回の検証はJavaScript構文、データ不変条件、意味契約、
章末ランダム生成をNode上で検証したもの。
実ブラウザE2Eではない。
