FE QUEST v59 - VERSION SYNC AUDIT

Root cause of the screenshot mismatch:
- index.html APP_VERSION was still v47.
- pwaVersionStatus initial HTML was v47.
- sw.js APP_VERSION was still v47.
- Later releases had only changed the cache name, not these version strings.

v59 fix:
- index APP_VERSION = v59
- initial version card = -- (never hardcodes an old release)
- refreshPwaHealth always renders APP_VERSION
- sw.js APP_VERSION = v59
- cache = fe-quest-v59-1
- app asks the active Service Worker for its version
- if page and Service Worker versions differ, the version card warns "更新必要"

This makes stale-version mismatches detectable instead of silently displaying an old number.

Runtime regression:
APP_VERSION_V59_OK
VERSION_CARD_V59_OK
VERSION_MISMATCH_WARNING_OK

Runtime validation used a Node VM DOM stub, not a real-browser E2E test.
